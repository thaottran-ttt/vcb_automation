# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

VCB_Regression (`RBTS.prj`) is a Katalon Studio ENTERPRISE mobile automation project for Vcb's VCB app
(and a thinner M2U website layer). It is a regression pack: ~1400+ test cases across modules (transfers,
DuitNow, Secure2u, Tabung, Fixed Deposit, onboarding, etc.), written as Groovy scripts driving Appium.

## Working with this project

This project uses **apac-sdlc**. Bundled skills live in `.claude/skills/` and
are available as slash commands (e.g. `/apac-sdlc-code-review`,
`/apac-sdlc-pr-description`). Project-specific rules and verbose docs are
imported from `.claude/rules/` and `.claude/docs/` below — keep this root
file as a lightweight index (≤ 200 lines).

## Build & Test

There is no gradle build/test task — `build.gradle` only declares `katalon-core` as a dependency for IDE
resolution. Tests are run from Katalon Studio (GUI), or via the Katalon CLI console runner against this
project's `RBTS.prj`, selecting a Test Suite (`Test Suites/**/*.ts`) and an execution profile (`Profiles/*.glbl`,
e.g. `vcb-regression` for the UAT/SIT target). There is no CI config in this repo.

```bash
# Console-mode run (adjust paths/profile/suite for your environment):
katalonc -noSplash -runMode=console \
  -projectPath="$(pwd)/RBTS.prj" \
  -retry=0 \
  -testSuitePath="Test Suites/<Group>/<Suite>" \
  -executionProfile="vcb-regression"
```

Never hand-edit `Libs/CustomKeywords.groovy` or `Libs/internal/GlobalVariable.groovy` — both are regenerated by
Katalon Studio from `Keywords/` and `Profiles/*.glbl`. Same for a suite's generated `.groovy` runner next to its `.ts`.

## Conventions

- `Test Cases/` and `Scripts/` mirror each other 1:1 by folder name; `Test Data/` holds the CSV/XLSX data a case reads.
- New page objects need a base abstract class under `internal/pages/base/` **and** a concrete
  `AndroidPhone<Name>Page` under `internal/pages/androidphone/`, even if the Android class overrides nothing —
  `BasePage.getPage()` resolves the implementation via reflection and throws if it's missing.
- Only Android device implementations exist; iOS/tablet `DeviceTypeEnum` cases are declared but unimplemented.
